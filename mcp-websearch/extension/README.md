# Расширение моста (уровень 4)

Собственное MV3-расширение без единой зависимости: связывает реальный
браузерный профиль пользователя с локальным `mcp-websearch` (модуль
`../`, Go-бинарь). Мост поднимается лениво — первым вызовом
`bridge_status` / `profile_fetch` / `profile_tab` или
`mcp-websearch --selftest-bridge`. Никаких внешних сервисов: весь трафик —
`127.0.0.1:8765` и целевые сайты от имени этого браузера.

## Установка (Edge, Chrome, Chromium; «Load unpacked»)

1. Собери и поставь бинарь (один раз):
   ```bash
   cd ~/dev/mini-mcp/mcp-websearch
   go build -o ~/bin/mcp-websearch .
   ```
2. Подними мост и создай токен (файл появится сам):
   ```bash
   ~/bin/mcp-websearch --selftest-bridge
   # → «FAIL: extension offline» — это нормально на первом запуске;
   #   токен уже создан: ~/.config/mcp-browserbridge/token
   cat ~/.config/mcp-browserbridge/token
   ```
3. Браузер → `edge://extensions` (или `chrome://extensions`) →
   включи «Режим разработчика» → **Load unpacked / Загрузить
   распакованное** → выбери каталог `~/dev/mini-mcp/mcp-websearch/extension`.
4. В карточке расширения → «Параметры / Options» → вставь токен →
   «Сохранить» → «Проверить связь» (должно быть «OK — мост отвечает»).
   Мост должен быть поднят (шаг 2 оставляет его жить, пока жив процесс;
   иначе вызови любой bridge-инструмент агента — он поднимет мост лениво).
5. Повтори `~/bin/mcp-websearch --selftest-bridge` → ждём
   `selftest-bridge: PASS` (example.com через реальный профиль).

## Как это работает

- `background.js` (service worker) раз в ~1с делает `GET /job` на
  `127.0.0.1:8765` с заголовком `X-Bridge-Token`. 204 → спит; 200 →
  исполняет задание и отправляет `POST /result/{id}`. Сам поллинг держит
  воркер живым (MV3-keepalive), `chrome.alarms` 30с — страховка.
- `fetch` — сетевой запрос **из профиля браузера**: куки, логины,
  отпечаток. Отдаёт HTTP-статус + тело (чарсет из заголовка или
  `<meta charset>`, кап 5MB).
- `tab_read` — навигация в **одной закреплённой видимой вкладке**
  (переиспользуется: сессия и куки живут), пауза на JS, затем чтение
  `{title, url, innerText}`. Это самый «честный» сигнал для антиботов.
- Темп задаёт сервер (`--min-interval`, 2с): расширение не умеет
  слать быстрее, чем мост выдаёт задания.

## Смена порта (кэвэт)

Порт `8765` зашит в **двух** местах: `manifest.json`
(`host_permissions`) и флаге бинаря `--bridge-port`. Менять — только
в обоих (плюс поле «Порт» в настройках расширения).

## Приватность

- Расширение никуда не звонит, кроме `127.0.0.1:<port>` и адресов,
  которые мост прямо передал для задания.
- Токен — локальный файл `~/.config/mcp-browserbridge/token` (0600),
  он же в `chrome.storage.local`. Параметр `token` в настройках —
  единственная «секретная» часть расширения.
- Никакого удалённого кода, аналитики и внешних CDN.

## Отладка

- `edge://extensions` → карточка расширения → «service worker» —
  консоль с логами `[bridge] job <id> …`.
- `bridge_status` (инструмент агента) показывает роль (owner/client),
  живость расширения (online/offline по последнему опросу) и адрес.
- 401 в цикле = токен не совпал; connection refused = мост не поднят
  (см. шаг 2) или владелец умер — расширение само переподключится ~5с.
