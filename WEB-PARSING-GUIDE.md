# Гайд: веб-поиск и парсинг (Ozon и не только) без квот через локальный MCP

Дата: 2026-10-18. Источник — натурные эксперименты на этой машине (macOS,
резиденциальный IP, Москва). Всё проверено живьём: Ozon спарсен дважды, капч — ноль.

---

## 1. Зачем это всё

Coding-план z.ai квотирует hosted-инструменты `web-search` и `web-reader`
(ресет 2026-11-05). Их вызовы дороги. Всё описанное ниже **бесплатно**: поиск,
чтение страниц и браузерный парсинг выполняются локально и не проходят через
Z.ai. Единственный расход — токены модели (обычная генерация).

Лестница инструментов (пробовать по порядку, сверху вниз):

| Уровень | Инструмент | Проходит | Ломается на |
|---|---|---|---|
| 1 | `web_search` (MCP mcp-websearch) | любые сайты — запрос идёт в DDG/Bing, целевой сайт нас не видит | практически никогда |
| 2 | `read_url` (MCP mcp-websearch) | статика/SSR: доки, GitHub, вики, новости, блоги | JS-only SPA (пусто); антибот-WAF; логин-контент |
| 3 | Встроенный браузер ZCode (плагин browser-use, бэкенд IAB) | + JS, SPA, большинство антиботов — **Ozon проходит** | **WB**: интерстишл «Подозрительная активность» с таймером-ловушкой — НЕ пробивать (см. §2а) |
| 4 | Реальный Chrome юзера (Browser MCP, browsermcp.io — пока не ставили) | + логины/куки/персонализация | — |

Правило: `web_search` нашёл ссылки → сайт «жёсткий» (Ozon, WB, Avito,
Яндекс-сервисы, что-то за Cloudflare) → сразу уровень 3, `read_url` даже не
пробуем. Для статичных сайтов хватит уровней 1–2 без браузера вообще.

## 2. MCP mcp-websearch — установка и использование

Модуль: `~/dev/mini-mcp/mcp-websearch/` (Go, отдельный модуль репо mini-mcp,
идиомы mcp-pg-readonly). Один статический бинари, ни Node, ни секретов.

```bash
cd ~/dev/mini-mcp/mcp-websearch
go test ./...                          # юнит-тесты (без сети)
go build -o ~/bin/mcp-websearch .      # сборка + установка
~/bin/mcp-websearch --selftest         # живая проверка: реальный поиск + чтение
```

Регистрация в ZCode — `~/.zcode/cli/config.json` → `mcp.servers`:

```json
"websearch": {
  "type": "stdio",
  "command": "/Users/ilkoid/bin/mcp-websearch",
  "args": [],
  "timeoutMs": 60000
}
```

Регистрация в AutoClaw/OpenClaw — `~/.openclaw-autoclaw/openclaw.json` →
`mcp.servers` (подхватывается без перезапуска; их UI stdio-серверы в списке
не показывает — истиной является доступность инструментов агенту):

```json
"websearch": {
  "type": "stdio",
  "command": "/Users/ilkoid/bin/mcp-websearch",
  "enabled": true
}
```

### web_search

Вход: `query` (обяз.), `engine` = `auto|ddg|bing` (авто = DDG, при
403/пусто — Bing с пометкой в `notice`), `max_results` (дефолт 10, кап 20).

Выход: `{query, engine, notice?, results: [{title, url, snippet}]}`.
Без JS, без ключей; движки — plain-HTML SERP (html.duckduckgo.com, bing.com).
Работают и `site:`-запросы (напр. `site:ozon.ru куртка playtoday`) — удобно
искать конкретный сайт, вообще его не трогая.

### read_url

Вход: абсолютный http(s) URL. Выход:
`{url, title, content_type, truncated, notice?, text}` — читаемый текст,
кап 48KB, понимает windows-1251 и мета-чарсеты. Бинарные content-type
отклоняет с подсказкой. Не JS-браузер: SPA отдаст мало текста.

### Наблюдения по границам (эмпирика)

- DDG с резиденциального IP + честного UA — стабильно без блоков. Bing — 200.
  Google без JS не отдаёт выдачу — не пытаться, это уровень 3.
- Ozon на plain GET отвечает 307-лупом с JS-челленджем `__rr=N` и заглушкой
  ~164 байта. Это не бан и не «страйк» — просто глухая дверь без JS-движка.

### 2а. WB / wildberries.ru — закрыт на всех уровнях (проверено 2026-11-12)

- Plain HTTP: нестандартный **HTTP 498** («нет валидного токена») + JS-заглушка
  ~1KB; `wb.ru` при этом редиректит на `www.wildberries.ru`.
- Настоящий Chromium (IAB, свежая вкладка): интерстишл **«Что-то не так…
  Подозрительная активность. Новая попытка через ~60с»** с ID и IP в тексте.
  Это **таймер-ловушка**: ожидание и повторная попытка подтверждают
  подозрения и создают риск бана IP. По опыту — не пробивается.
- **Политика: WB не парсить этой лестницей вообще.** Данные WB — только
  через официальный конвейер/API (в нашей экосистеме — downloaders poncho-ai,
  база `wb_data_prod`). Ozon остаётся единственным маркетплейсом, который
  стабильно проходится браузерным уровнем.
- Баны у Ozon вешают за скрейпинг-паттерны: сотни запросов в минуту,
  datacenter-IP, отсутствие JS. Профиль «1–3 запроса + настоящий Chromium с
  JS с домашнего IP» от человека неотличим (см. §4).

## 3. Если в проекте нужен не агент, а код

Бинари — самостоятельный stdio JSON-RPC сервер. Любой MCP-клиент может его
поднять (ZCode, AutoClaw, Claude, самописный процесс): спавнишь процесс,
говоришь MCP-протокол — получаешь те же два инструмента. Альтернатива —
тащить логику из исходников `search.go`/`readurl.go` к себе (там goquery,
charset-декодинг, парсеры DDG/Bing с unwrap'ом их редирект-обёрток
`duckduckgo.com/l/?uddg=` и `bing.com/ck/a?u=a1<base64url>`).

## 4. Методика парсинга Ozon через встроенный браузер (отработанная)

Контекст: ZCode-плагин browser-use, бэкенд IAB (настоящий Chromium-вьювнутри
приложения, панель видна юзеру). Управление — через MCP-инструмент
`mcp__node_repl__js` (каждый вызов = свежее JS-ядро; вкладки браузера живут
между вызовами — они и есть «сессия»).

### Главный принцип «косим под реального пользователя»

- **Один таб на всё.** Куки, выданные после первого челленджа, живут в
  сессии IAB — переиспользуем вкладку, не плодим новые. Новая «чистая»
  вкладка = снова челлендж.
- **Человеческий темп.** Пауза ~3 сек между карточками, 2 карточки на один
  js-вызов, после поиска — пауза ~5 сек (челлендж резолвится JS пару секунд).
- **Объём.** ~11 запросов за прогон (1 поиск + 10 карточек), до ~30 в день —
  ноль капч за все эксперименты. Раз в день такой срез — безопасно.
- **Не делать:** параллельные табы, десятки запросов подряд, обход капчи
  трюками. Появилась капча — стоп, подождать/сократить частоту. Никакого
  «прорыва» — это мониторинг публичных данных в человекочитаемом объёме.

### Схема прогона

1. **Собрать выдачу.** Навигация на поисковый URL, ждать domcontentloaded
   + 5 сек, собрать ссылки скриптом в контексте страницы.

   Поисковый URL: `https://www.ozon.ru/search/?text=<encodeURIComponent(q)>`.
   Ozon сам применит предсказание категории и/или бренд-фильтр (увидишь в
   итоговом URL `brand=<id>` / `category=<slug>-<id>`) — это нормально.

2. **Выделить артикулы (SKU).** Артикул = хвостовое число в URL карточки:
   `/product/<slug>-<sku>/`. Дедуп по SKU (в выдаче одна карточка даёт
   несколько ссылок с разными tracking-параметрами `?at=`).

3. **Пройти карточки.** goto + 3 сек, извлечь данные (см. селекторы ниже),
   пауза 3 сек, следующая.

4. **Извлечение со страницы товара:**

| Данные | Откуда |
|---|---|
| Название | `document.querySelector('h1').innerText` |
| Цены | `[data-widget="webPrice"]` innerText, регекс `/(\d[\d\s\u00A0]{2,9})\s*₽/g` по нему. **Порядок: 1-я = с Ozon-картой, 2-я = базовая, 3-я (если есть) = «с другими банками»** (в мониторинг брать первые две) |
| Материал | строка после метки в `document.body.innerText`: сначала искать `'Основной материал'`, затем `'Материал'` (на части карточек первого поля нет). Внимание: `'Материал'` может матчнуть и «Материал подкладки» — если важна точность, парсить DOM-секцию характеристик, а не текст |
| Остатки | регекс `/Осталось (?:мало|\d+ шт)/` по innerText (метки SERP на карточке могут не подтверждаться) |
| Рейтинг | виджет отзывов; простым регексом по тексту ловится нестабильно — при необходимости парсить DOM |

### Наблюдения по Ozon-выдаче (важно для интерпретации данных)

- **Релевантность рыхлая.** По запросу с явным брендом Ozon включает
  бренд-фильтр и тащит ВСЕ товары бренда (перчатки в выдаче «курток»).
  По запросу без бренда — ранжирует по предсказанной категории, топ забит
  смежными категориями. Для конкурентного среза фильтруй результат по
  названию/категории, а не доверяй выдаче как истине.
- Цены всегда в двух-трёх ярусах; сравнивать конкурентов корректно по
  **базовой** (2-й) цене, «с Ozon-картой» — промо-витрина.
- URL выдачи/карточок содержат трекинг (`?at=`, `?sh=`) — для навигации
  сохранять как есть (реалистичнее), для хранения данных — чистить до
  pathname.

### Каркас кода (реально работавший, обобщённый)

```js
// Бутстрап — в начале КАЖДОГО js-вызова (ядро каждый раз свежее):
const browserPluginRoot =
  process.env.ZCODE_PLUGIN_ROOT ?? process.env.CLAUDE_PLUGIN_ROOT;
const { join } = await import("node:path");
const { pathToFileURL } = await import("node:url");
const { setupBrowserRuntime } = await import(
  pathToFileURL(join(browserPluginRoot, "scripts", "browser-client.mjs")).href
);
await setupBrowserRuntime({ globals: globalThis });
const browser = await agent.browsers.getForUrl("https://www.ozon.ru/");

// Привязать существующий таб (куки!):
const tabs = await browser.tabs.list();
const tab = await browser.tabs.get(tabs.find(t => t.url?.includes("ozon.ru")).id);

// --- Шаг 1: поиск ---
await tab.goto("https://www.ozon.ru/search/?text=" + encodeURIComponent(q));
await tab.playwright.waitForLoadState({ state: "domcontentloaded" });
await tab.playwright.waitForTimeout(5000);

const serp = await tab.playwright.evaluate(`(() => {
  const out = [], seen = new Set();
  for (const a of document.querySelectorAll('a[href*="/product/"]')) {
    const m = a.pathname.match(/-(\\d{6,})\\/?$/);
    if (!m || seen.has(m[1])) continue;
    seen.add(m[1]);
    out.push({ sku: m[1], url: a.origin + a.pathname });
    if (out.length >= 10) break;
  }
  return out;
})()`);

// --- Шаг 2: карточки (по 2 за вызов, паузы 3с) ---
for (const { sku, url } of serp.slice(0, 2)) {
  await tab.goto(url);
  await tab.playwright.waitForLoadState({ state: "domcontentloaded" });
  await tab.playwright.waitForTimeout(3000);
  const info = await tab.playwright.evaluate(`(() => {
    const h1 = document.querySelector('h1');
    const title = h1 ? h1.innerText.replace(/\\s+/g,' ').trim() : document.title;
    const wp = (document.querySelector('[data-widget="webPrice"]')?.innerText || '')
      .replace(/\\s+/g,' ').trim();
    const prices = [];
    const re = /(\\d[\\d\\s\\u00A0]{2,9})\\s*₽/g; let m;
    while ((m = re.exec(wp)) && prices.length < 4)
      prices.push(Number(m[1].replace(/[\\s\\u00A0]/g,'')));
    const body = document.body.innerText || '';
    const after = (label) => {
      const i = body.indexOf(label);
      return i < 0 ? null
        : body.slice(i + label.length).trim().split('\\n')[0].slice(0, 50) || null;
    };
    const material = after('Основной материал') || after('Материал');
    return { title, prices, material };
  })()`);
  console.log(sku, JSON.stringify(info));
  await tab.playwright.waitForTimeout(3000);
}
```

## 5. Результаты натурных экспериментов (2026-10-18)

**Эксперимент A — свой бренд.** Запрос «осенние куртки для мальчика
подростка playtoday» → Ozon авто-применил `brand=19762580`, в выдаче ~16
товаров. Собраны артикулы+цены топ-10: перчатки 807 ₽ … пуховик 12 756 ₽,
куртки 4.3–12.8k, пальто 6.0–7.7k. Разрыв «с картой/без» стабильно ~5%.

**Эксперимент B — конкуренты.** Запрос «брюки школьные для мальчика»
(без бренда) → авто-категория «Школьная форма для мальчиков». Топ-10:
WEEBEES, ELINAS-SHOP, FUNDAY×2, NeSchool, TMK, Апрель Школа, Daniele
Patrici, VINISWAG. Цены 551–2 625 ₽ (медиана ~1.4k), материалы собраны —
два кластера: костюмные ткани (вискоза/полиэстер/шерсть) vs трикотаж/футер.

**WAF-счёт:** суммарно 22 запроса к Ozon за обе сессии, темп 3с, один таб —
**ноль капч, ноль блоков**.

**Эксперимент C — WB (2026-11-12), отрицательный результат.** Plain-HTTP:
HTTP 498 + JS-заглушка. IAB-браузер (свежая вкладка): интерстишл
«Подозрительная активность» с таймером ~60с — ловушка, попытка прекращена,
вкладка закрыта. Вывод в §2а: WB закрыт для этой лестницы, данные —
только через официальный конвейер/API.

## 6. Эскалация и поддержка

- DDG/Bing начали отдавать 403/капчу mcp-websearch'у → использовать
  `engine=ddg|bing` явно, затем уровень 3 (браузер). Обходных трюков не
  городить — это осознанная политика.
- Нужны логины/персональные цены → уровень 4: Browser MCP (browsermcp.io):
  расширение в Chrome + сервер `npx -y @browsermcp/mcp`, регистрация как у
  любого stdio-сервера. Не проверялось на этой машине.
- Изменения в mcp-websearch: правила репо mini-mcp (AGENTS.md) — stdout
  sacred, ошибки в CallToolResult, тесты на фикстурах, selftest.
